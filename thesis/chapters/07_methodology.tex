\chapter{Experimental methodology}
\label{cha:methodology}

This chapter defines exactly how the three hypotheses from \Cref{sec:introduction-goal} are tested. Because the claims this thesis makes are comparative -- one configuration is more accurate than another -- almost all of the methodological effort goes into making sure that a measured difference can only be attributed to the thing that was deliberately changed. That concern shapes three decisions described below: the grid varies one factor at a time from a fixed baseline, everything is repeated because neither the system nor the instrument measuring it is deterministic, and the qualitative scoring stage is replicated across two independent judges precisely because that instrument is another language model and cannot be assumed neutral.

Repetition happens on two independent axes, and keeping them apart matters for reading the numbers that follow. Every cell of both experimental grids -- one combination of model, system variant and scenario -- is planned three times, which samples the generating model's own nondeterminism. Each of those runs is then scored three times by each judge, which samples the judge's. The first axis is what \Cref{sec:methodology-stability} quantifies as run-to-run variability; the second is averaged away as described in \Cref{sec:methodology-qualitative}. With that established, the chapter states the research questions, defines the two grids and the scenarios they run against, and specifies every metric reported in \Cref{cha:results}.

\section{Research questions}
\label{sec:methodology-research-questions}

The hypotheses in \Cref{sec:introduction-goal} translate into three concrete research questions.

\begin{description}
    \item[RQ1] By how much does enabling the deterministic totaller reduce energy and macronutrient error?
    \item[RQ2] By how much does enabling the critique-and-refine loop reduce energy and macronutrient error and improve adherence to the stated constraints and preferences, on its own and on top of the totaller?
    \item[RQ3] How does plan quality vary with the choice of language model and with its reasoning-effort level, and can raising the effort level substitute for a stronger model?
\end{description}

RQ1~and RQ2~are answered by a single \emph{component ablation} experiment (\Cref{sec:methodology-variants}) that holds the language model fixed and varies only the totaller and reflection flags. RQ3~is answered by a separate \emph{model comparison} experiment that holds the system configuration fixed at its strongest setting and varies the model and its reasoning-effort level together, as described in \Cref{sec:methodology-model-grid}.

As established in \Cref{sec:vision-food-lookup-baseline}, food knowledge base access is not one of the varied flags: it is present, identically configured, in every one of the four variants, so that \emph{baseline} in this experiment denotes a system that already looks up real foods and simply lacks the two optional grounding and review mechanisms under study, not a system reasoning about nutrition from the language model's own memory.

\section{Model and reasoning-effort grid}
\label{sec:methodology-model-grid}

The model comparison experiment fixes the system at the full variant and varies the generating model instead. Two things are varied at once, deliberately: the base model, and the reasoning-effort level that model is asked to run at. Four base models are compared, each at three effort levels, giving twelve configurations. Where a provider's default effort already falls at one of the three levels being compared, that default is used as the level rather than re-requesting it explicitly, so a configuration is identified by a model together with the effort it actually ran at.

Two properties of this design matter for interpreting the results. Within one base model the three configurations differ only in effort, so a difference between them is attributable to deliberation alone. Across base models, by contrast, the effort labels are each vendor's own and carry no guarantee of comparability -- one provider's \emph{high} may buy considerably more or less internal computation than another's -- so the aggregate comparison across effort levels in \Cref{sec:results-effort} groups vendor-specific labels into three coarse buckets and should be read as an indication of direction rather than as a calibrated measurement. Each of the twelve configurations is run against all five scenarios, giving 180 runs. Fifteen of these coincide exactly with the full-variant cell of the ablation experiment and are stored and scored once, so the two experiments together comprise 225 distinct runs.

The reasoning-effort setting is applied only to the agents whose output affects plan correctness -- the nutrition agent, the critic and the refiner -- as described in \Cref{sec:design-agents}. The judges are not affected by it: they run at their own providers' defaults regardless of which configuration produced the plan they are scoring, so that the measuring instrument does not change as the object of measurement does.

\section{Scenarios and profiles}
\label{sec:methodology-scenarios}

Each evaluated run pairs a fixed user profile with a scenario: an optional free-form session request and, where applicable, a set of scenario-specific soft criteria scored by the qualitative judges (\Cref{sec:methodology-qualitative}). Five scenarios were selected for the main experimental grid, listed in \Cref{tab:methodology-scenarios}. They were chosen to differ in what they demand of the system rather than to sample a population: one asks for nothing beyond a coherent day of food, two set a hard exclusion against an explicit user request for something that would violate it, and two impose interacting chronic conditions whose dietary guidance pulls in several directions at once.

Each scenario's underlying profile is frozen ahead of time -- age, sex, body measurements, activity level, dietary goal, allergies, diagnosed conditions and standing preferences are all fixed -- and each profile carries a frozen set of energy and macronutrient targets computed independently of the pipeline under test, so that every run's reported error is measured against the same target regardless of which variant or model produced the plan.

\section{Quantitative scoring: energy and macronutrient error}
\label{sec:methodology-quantitative}

The quantitative scoring stage measures how closely a plan's delivered energy and macronutrient totals match their targets, using the same deterministic aggregator described in \Cref{sec:design-totaller} to compute the delivered values -- independently of whether the totaller tool was available to the model during generation, so that even a baseline-variant plan's accuracy is judged by a real, exactly computed total rather than by anything the model claimed.

For each tracked nutrient $n$ (energy, protein, carbohydrates, and fat) with a positive target, a signed relative error is computed as
\[
    \mathrm{rel}_n = \frac{\mathrm{actual}_n - \mathrm{target}_n}{\mathrm{target}_n} \times 100\%,
\]
where $\mathrm{actual}_n$ is the deterministically computed total for a hydrated plan and $\mathrm{target}_n$ is the profile's frozen target for that nutrient. Each run is summarised by the mean absolute and the mean squared value of $\mathrm{rel}_n$, referred to below as $\mathrm{MAE\%}$ and $\mathrm{MSE\%}$.

Expressing the error relative to its target rather than in absolute nutrient units is what keeps a single figure comparable across nutrients measured on very different scales -- kilocalories against grams of fat, for instance. Both statistics are reported because the failure this evaluation is most interested in is the occasional badly wrong plan rather than a uniform drift away from target, and the two separate those cases. Because both are computed from the stored plan by a deterministic routine, they do not depend on the judges at all, and are identical no matter which judge's records they are read from.

\section{Qualitative scoring: the judge protocol}
\label{sec:methodology-qualitative}

Everything not captured by an energy or macronutrient number -- whether a recipe is physically coherent, whether a stated allergen was actually avoided, whether an explicit session request was honoured without violating a harder constraint -- is scored by an LLM-as-a-judge stage following the G-Eval pattern described in \Cref{sec:background-evaluation}: a judge model is given an explicit natural-language rubric per criterion and asked to produce both a score and a short justification, rather than a bare number with no accompanying reasoning.

Every run is scored on one criterion present in all scenarios (whether the generated recipes are physically and logically coherent) plus every scenario-specific soft criterion listed for it in \Cref{sec:methodology-scenarios} -- for instance, whether a DASH-appropriate sodium-to-potassium balance was targeted, or whether a stated food preference was honoured without including a disliked food. Each criterion is scored on a continuous $[0, 1]$ scale, and a per-run \emph{soft aggregate} is reported as the mean of all criterion scores for that run. Two further, always-scored fields report \emph{safety adherence} -- a $[0, 1]$ score specifically for whether the plan's allergen exclusions and diet pattern were respected -- and a list of concrete \emph{safety violations} in free text where a judge identifies one, kept separate from the aggregate so that a single serious safety failure cannot be diluted into an otherwise unremarkable average. The judges are explicitly instructed not to penalise a plan for a missing micronutrient figure that the underlying food data itself does not cover, so that the coverage gaps described in \Cref{sec:impl-missing-nutrients} are not double-counted as a plan-quality failure on top of being flagged by the totaller's own coverage warnings.

An LLM judge is subject to well-documented biases -- a tendency to favour longer or more elaborately reasoned responses, and a self-preference bias when the judge shares a model family with the response under evaluation~\cite{zheng2023judging} -- and it is also a stochastic sampler, so it need not return the same verdict twice on an unchanged plan. Rather than assume either problem away, the protocol is built so that both become measurable, as motivated in \Cref{sec:impl-judges}:

\begin{itemize}
    \item \emph{Two judges, from different vendors.} Every plan is scored independently by both. One of them belongs to the same family as one of the compared configurations, which is exactly the situation self-preference bias would exploit; the other has no such overlap with any compared configuration. A family-specific bias therefore cannot hide, because it would appear as a divergence between two judges reading the same plans against the same rubric.
    \item \emph{Repeated scoring.} On the second of the two repetition axes, the verdicts a judge returns for a run are averaged before its qualitative score is used anywhere, which suppresses judge sampling noise without concealing how large it was.
    \item \emph{No averaging across judges.} Judge-dependent metrics -- the soft aggregate and safety adherence -- are carried through the whole reporting pipeline as two parallel series and always reported side by side. Collapsing them into one number would destroy precisely the disagreement the second judge exists to reveal.
\end{itemize}

\section{Stability metrics}
\label{sec:methodology-stability}

Two further quantities describe how repeatable a result is, rather than how good it is, and both are reported per judge.

The first is \emph{run-to-run variability}: how much the same configuration's soft aggregate moves when the identical request is planned again from scratch. Because the repetitions of one cell differ only in the language model's sampling, the \emph{spread} of that cell is defined as the mean absolute deviation of its soft aggregate about the cell's own mean:
\[
    \bar{s}_c = \frac{1}{R} \sum_{r=1}^{R} s_{c,r},
    \qquad
    d_c = \frac{1}{R} \sum_{r=1}^{R} \left| s_{c,r} - \bar{s}_c \right|,
\]
where:
\begin{itemize}
    \item \( c \) -- a cell, that is one combination of language model, system variant and scenario,
    \item \( R \) -- the number of repetitions of a cell,
    \item \( s_{c,r} \) -- the soft aggregate one judge awarded to repetition \( r \) of cell \( c \),
    \item \( \bar{s}_c \) -- the mean soft aggregate of cell \( c \),
    \item \( d_c \) -- the spread of cell \( c \).
\end{itemize}

Cell spreads are then averaged over the cells of a single model and over every cell of an experiment:
\[
    V_m = \frac{1}{\left| C_m \right|} \sum_{c \in C_m} d_c,
    \qquad
    V = \frac{1}{\left| C \right|} \sum_{c \in C} d_c,
\]
where:
\begin{itemize}
    \item \( C_m \) -- the set of cells whose language model is \( m \),
    \item \( C \) -- the set of all cells of the experiment,
    \item \( V_m \) -- the variability reported for model \( m \),
    \item \( V \) -- the pooled variability of the experiment.
\end{itemize}

The size of $V$ relative to the differences between configurations is what matters for this thesis: a spread of the same order as those differences means they cannot be read as real.

The second is the agreement between the two judges. Because both score every plan under an identical rubric, any systematic difference between their means is a property of the judges rather than of the plans, and any difference in how they \emph{rank} configurations is the more serious concern, since every comparative claim in \Cref{cha:results} depends on ranking. Both are reported in \Cref{sec:results-stability}.

\section{Operational metrics}
\label{sec:methodology-operational}

Two further figures are recorded per run without requiring any scoring step: the number of \emph{iterations} the critique-and-refine loop actually performed (zero when reflection is disabled, or when the critic approved the first draft outright) and the run's wall-clock \emph{elapsed time}. Token usage -- input, output and total tokens, and the number of separate model requests a run made -- is recorded alongside these to characterise the computational overhead of each mechanism in \Cref{sec:results-overhead}, though it plays no role in scoring a plan's quality. No monetary cost is reported anywhere in this thesis: converting tokens into money requires per-model prices that change without notice and differ by routing provider, which would make any figure quoted here both unverifiable and quickly wrong.
