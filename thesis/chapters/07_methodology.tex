\chapter{Experimental methodology}
\label{cha:methodology}

This chapter defines exactly how the three hypotheses from \Cref{sec:introduction-goal} are tested: the research questions they translate into, the experimental grid run to answer them, the test scenarios and user profiles used, and the precise definition of every metric reported in \Cref{cha:results}.

\section{Research questions}
\label{sec:methodology-research-questions}

The hypotheses in \Cref{sec:introduction-goal} translate into three concrete research questions.

\begin{description}
    \item[RQ1] How much does enabling the deterministic totaller, alone, change macronutrient accuracy relative to a plan produced without either grounding mechanism?
    \item[RQ2] How much does enabling the critique-and-refine loop, alone and in combination with the totaller, change macronutrient accuracy and adherence to stated preferences and constraints?
    \item[RQ3] How does the size of these effects change when the underlying language model's capability tier changes?
\end{description}

RQ1 and RQ2 are answered by a single \emph{component ablation} experiment (\Cref{sec:methodology-variants}) that holds the language model fixed and varies only the totaller and reflection flags; RQ3 is answered by a separate \emph{model comparison} experiment that holds the system configuration fixed at its strongest setting and varies only the underlying model.

\label{sec:methodology-scenarios}

Each scenario's underlying profile is frozen ahead of time -- age, sex, body measurements, activity level, dietary goal, allergies, diagnosed conditions and standing preferences are all fixed -- and each profile carries a frozen set of macronutrient targets computed independently of the pipeline under test, so that every run's reported error is measured against the same target regardless of which variant or model produced the plan.

\section{Quantitative scoring: macronutrient error}
\label{sec:methodology-quantitative}

The quantitative scoring stage measures how closely a plan's delivered macronutrients match its target, using the same deterministic aggregator described in \Cref{sec:design-totaller} to compute the delivered values -- independently of whether the totaller tool was available to the model during generation, so that even a baseline-variant plan's accuracy is judged by a real, exactly computed total rather than by anything the model claimed.

For each tracked macronutrient $n$ (energy, protein, carbohydrates, fat and fibre) with a positive target, a signed relative error is computed as
\[
    \mathrm{rel}_n = \frac{\mathrm{actual}_n - \mathrm{target}_n}{\mathrm{target}_n} \times 100\%,
\]
where $\mathrm{actual}_n$ is the deterministically computed total for a hydrated plan and $\mathrm{target}_n$ is the profile's frozen target for that nutrient. Two summary statistics are reported per run, averaged over the tracked macronutrients:
\[
    \mathrm{MAE\%} = \operatorname{mean}_n \left( \left| \mathrm{rel}_n \right| \right),
    \qquad
    \mathrm{MSE\%} = \operatorname{mean}_n \left( \mathrm{rel}_n^2 \right).
\]
$\mathrm{MAE\%}$ is unbounded above and zero only for a plan that matches every tracked macronutrient target exactly; $\mathrm{MSE\%}$ uses the same signed error but squared before averaging, and so penalises a single large deviation more heavily than several small ones of the same total magnitude. Both are reported as percentages of the corresponding target rather than in absolute nutrient units, so that a single figure is comparable across nutrients measured on very different scales (kilocalories against grams of fibre, for instance).

\section{Qualitative scoring: the judge rubric}
\label{sec:methodology-qualitative}

Everything not captured by a macronutrient number -- whether a recipe is physically coherent, whether a stated allergen was actually avoided, whether an explicit session request was honoured without violating a harder constraint -- is scored by an LLM-as-a-judge stage following the G-Eval pattern described in \Cref{sec:background-evaluation}: a judge model, kept fixed and distinct from every model under evaluation, is given an explicit natural-language rubric per criterion and asked to produce both a score and a short justification, rather than a bare number with no accompanying reasoning.

Every run is scored on one criterion present in all scenarios (whether the generated recipes are physically and logically coherent) plus every scenario-specific soft criterion listed for it in \Cref{sec:methodology-scenarios} -- for instance, whether a DASH-appropriate sodium-to-potassium balance was targeted, or whether a stated food preference was honoured without including a disliked food. Each criterion is scored on a continuous $[0, 1]$ scale, and a per-run \emph{soft aggregate} is reported as the mean of all criterion scores for that run. Two further, always-scored fields report \emph{safety adherence} -- a $[0, 1]$ score specifically for whether the plan's allergen exclusions and diet pattern were respected -- and a list of concrete \emph{safety violations} in free text where the judge identifies one, kept separate from the aggregate so that a single serious safety failure cannot be diluted into an otherwise unremarkable average. The judge is explicitly instructed not to penalise a plan for a missing micronutrient figure that the underlying food data itself does not cover, so that the coverage gaps described in \Cref{sec:impl-missing-nutrients} are not double-counted as a plan-quality failure on top of being flagged by the totaller's own coverage warnings.

Because an LLM judge is itself subject to the biases documented for this evaluation pattern -- a tendency to favour longer or more elaborately reasoned responses, and a self-preference bias when a judge happens to share a model family with the response under evaluation~\cite{zheng2023judging} -- the judge model used throughout this thesis's evaluation is deliberately kept constant and distinct from every model family compared in \Cref{sec:results-model-comparison}, and its rubric is applied identically across every variant and scenario so that any residual judge bias would need to interact with a specific variant or model in a way that is at least visible if not fully eliminated by holding the judge fixed.

\section{Operational metrics}
\label{sec:methodology-operational}

Two further figures are recorded per run without requiring any scoring step: the number of \emph{iterations} the critique-and-refine loop actually performed (zero when reflection is disabled, or when the critic approved the first draft outright) and the run's wall-clock \emph{elapsed time}. Token usage -- input, output and total tokens, and the number of separate model requests a run made -- is recorded alongside these for the cost and latency analysis in \Cref{sec:results-cost-latency}, though it plays no role in scoring a plan's quality.

\section{Repetitions, aggregation and reproducibility}
\label{sec:methodology-repetitions}

Because a language model's output is nondeterministic even at a fixed configuration, every (model, variant, scenario) combination in the main experimental grid is repeated several times, and every metric reported in \Cref{cha:results} at the level of a variant or a model is an arithmetic mean over its repetitions, with the corresponding population standard deviation reported alongside it as a measure of run-to-run variability. Every scored run is persisted individually before any aggregation happens, and the run collector described in \Cref{sec:impl-eval-harness} is fully resumable, so that the exact same aggregate figures reported here can be reproduced by re-running the collection and scoring commands against the same stored artefacts, and the grid can be extended with further repetitions or further models at any time without discarding or re-computing anything already collected.
